# Unix Shell Emulator

Учебный проект на языке Go, реализующий простой эмулятор Unix shell.

Программа поддерживает запуск в интерактивном режиме и выполнение команд из startup-скрипта.

## Возможности

На текущем этапе реализованы:

- запуск эмулятора из командной строки;
- интерактивный режим;
- выполнение команд из скрипта;
- команда `ls`;
- команда `cd`;
- команда `exit`;
- обработка неизвестных команд;
- подстановка переменных окружения;
- настраиваемый prompt;
- параметр для указания пути к виртуальной файловой системе;
- остановка startup-скрипта при ошибке команды.

> В текущей версии `--vfs-path` принимается программой, но полноценная работа с виртуальной файловой системой ещё не реализована.

```text
project/
├── go.mod
├── README.md
├── run.sh
├── src/
│   ├── main.go
│   ├── executor.go
│   ├── runner.go
│   └── promt.go
└── tests/
    ├── test_commands.sh
    ├── test_errors.sh
    ├── test_startup.sh
    └── run_tests.sh
```

### `src/`

Содержит исходный код программы.

- `main.go` — запуск программы, обработка параметров командной строки и интерактивный режим.
- `executor.go` — выполнение команд.
- `runner.go` — чтение и выполнение команд из startup-скрипта.
- `promt.go` — создание prompt.

### `tests/`

Содержит shell-тесты программы.

Тесты запускают эмулятор как обычную программу и проверяют его поведение.

# Требования

Для запуска необходим:

- Go;
- Unix-подобный shell (`sh`) для запуска тестов.

Проверить установленную версию Go:

```bash
go version
```

# Запуск программы

Перейдите в корневую директорию проекта:

```bash
cd project
```

После этого программу можно запустить через `run.sh`:

```bash
./run.sh
```

Если `run.sh` ещё не имеет права на выполнение:

```bash
chmod +x run.sh
```

После запуска появится prompt, например:

```text
(EMU)user@computer:/path/to/project$
```

Теперь можно вводить команды.

Например:

```text
ls
cd /tmp
exit
```

# Запуск напрямую через Go

Программу также можно запустить непосредственно из директории `src`:

```bash
cd src
go run .
```

Команда `go run .` означает:

> собрать и запустить Go-программу из текущей директории.

Все файлы:

```text
main.go
executor.go
runner.go
promt.go
```

относятся к одному пакету и собираются вместе.

# Параметры запуска

Программа поддерживает три параметра:

```text
--vfs-path
--prompt
--script-path
```

## `--vfs-path`

Указывает путь к виртуальной файловой системе.

Пример:

```bash
./run.sh --vfs-path ./test-vfs
```

Здесь:

```text
./
```

означает текущую директорию, а:

```text
test-vfs
```

— каталог виртуальной файловой системы.

Полный пример:

```bash
./run.sh --vfs-path ./test-vfs
```

> В текущей версии программа получает этот путь, но команды `ls` и `cd` ещё не работают с VFS.

---

## `--prompt`

Позволяет изменить внешний вид командной строки.

Пример:

```bash
./run.sh --prompt '{user}@{host}:{cwd}$ '
```

В prompt поддерживаются следующие переменные:

| Переменная | Значение |
|---|---|
| `{user}` | имя текущего пользователя |
| `{host}` | имя компьютера |
| `{cwd}` | текущая директория |

Например:

```text
{user}@{host}:{cwd}$
```

может превратиться в:

```text
alex@computer:/home/alex/project$
```

---

## `--script-path`

Указывает startup-скрипт, команды которого нужно выполнить сразу после запуска программы.

Например:

```bash
./run.sh --script-path ./scripts/start.sh
```

Если файл содержит:

```text
ls
cd /tmp
```

программа выполнит эти команды последовательно.

---

# Комбинация параметров

Параметры можно использовать одновременно:

```bash
./run.sh \
  --vfs-path ./test-vfs \
  --prompt '{user}@{host}:{cwd}$ ' \
  --script-path ./tests/startup.sh
```

Здесь используется синтаксис shell.

Символ:

```text
\
```

означает, что команда продолжается на следующей строке.

Ту же команду можно записать в одну строку:

```bash
./run.sh --vfs-path ./test-vfs --prompt '{user}@{host}:{cwd}$ ' --script-path ./tests/startup.sh
```

# Поддерживаемые команды

## `ls`

Команда просмотра содержимого директории.

Примеры:

```text
ls
ls -a
ls -l
```

На текущем этапе команда является упрощённой реализацией и выводит полученные аргументы.

---

## `cd`

Команда изменения директории.

Пример:

```text
cd /tmp
```

Также поддерживается проверка количества аргументов.

Например:

```text
cd /tmp /home
```

приведёт к ошибке:

```text
cd: too many arguments
```

> В текущей версии `cd` ещё не изменяет реальную виртуальную файловую систему.

---

## `exit`

Завершает работу эмулятора:

```text
exit
```

Команда не должна получать аргументы.

Например:

```text
exit now
```

приведёт к ошибке:

```text
exit: too many arguments
```

---

## Неизвестная команда

Если команда не поддерживается, программа выводит:

```text
command: command not found
```

Например:

```text
shalom
```

даст:

```text
shalom: command not found
```

При выполнении startup-скрипта после такой ошибки выполнение скрипта прекращается.

---

# Переменные окружения

Перед выполнением команды программа выполняет подстановку переменных окружения.

Например:

```text
ls $HOME
```

переменная:

```text
$HOME
```

будет заменена значением переменной окружения `HOME`.

Проверить это можно через startup-скрипт или интерактивный режим.

---

# Startup-скрипт

Startup-скрипт — обычный текстовый файл, содержащий команды эмулятора.

Например:

```text
ls
ls $HOME
cd /tmp
```

Запуск:

```bash
./run.sh --script-path ./scripts/start.sh
```

Программа:

1. открывает файл;
2. читает его построчно;
3. пропускает пустые строки;
4. пропускает строки, начинающиеся с `#`;
5. выводит выполняемую команду;
6. передаёт её исполнителю;
7. останавливается при ошибке.

# Тестирование

Для проекта используются отдельные shell-тесты.

Все тесты находятся в:

```text
tests/
```

Это означает, что тесты не находятся внутри `src/`.

`src/` содержит только код приложения, а `tests/` — проверку приложения.

---

## Запуск всех тестов

Сначала сделайте тестовые файлы исполняемыми:

```bash
chmod +x tests/*.sh
```

После этого из корня проекта выполните:

```bash
./tests/run_tests.sh
```

Скрипт последовательно запускает все тесты.

Пример успешного результата:

```text
Running tests...

Test 1: basic commands
PASS

Test 2: script stops on error
PASS

Test 3: startup script
PASS

All tests passed!
```

---

# Тест 1 — основные команды

Файл:

```text
tests/test_commands.sh
```

Проверяет запуск программы и выполнение базовой команды.

Например, тест передаёт программе:

```text
ls
exit
```

и проверяет, что `ls` действительно был выполнен.

Запуск отдельно:

```bash
./tests/test_commands.sh
```

Ожидаемый результат:

```text
Test 1: basic commands
PASS
```

---

# Тест 2 — обработка ошибок

Файл:

```text
tests/test_errors.sh
```

Проверяет, что неизвестная команда приводит к ошибке и startup-скрипт прекращает выполнение.

Например:

```text
ls
unknown-command
ls
```

После:

```text
unknown-command
```

последняя команда не должна выполняться.

Тест проверяет:

- наличие сообщения `command not found`;
- наличие сообщения об остановке скрипта;
- отсутствие выполнения команды после ошибки.

Запуск отдельно:

```bash
./tests/test_errors.sh
```

---

# Тест 3 — startup-скрипт

Файл:

```text
tests/test_startup.sh
```

Проверяет параметр:

```text
--script-path
```

Тест запускает программу с startup-скриптом и проверяет, что команды из него были выполнены.

Запуск отдельно:

```bash
./tests/test_startup.sh
```

---

# Запуск тестов по отдельности

Любой тест можно запустить отдельно:

```bash
./tests/test_commands.sh
```

```bash
./tests/test_errors.sh
```

```bash
./tests/test_startup.sh
```

Для запуска всех тестов:

```bash
./tests/run_tests.sh
```

Из корневой директории проекта:
